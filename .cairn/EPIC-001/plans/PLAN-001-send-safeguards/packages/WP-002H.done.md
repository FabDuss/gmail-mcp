### Slice

A client calls a sending tool while sending is off. The code already refuses it first in `GmailMCP.api`, ahead of the session owner check and the rate limiter, and already judges a path sending only when it resolves exactly to `messages.send` or `drafts.send`, with an undecodable path not sending. No test observes the order of the refusal, the exact match, or the undecodable path, so three mutants survived. This work-package adds tests that observe them and changes no behaviour. At the end, moving the refusal after the owner check or the rate limiter, turning the exact match into a prefix match, or answering `true` for an undecodable path fails a test.

### Needs

None closed. The tests guard what WP-002 delivered for NEED-005 Sending is refused while sending is off: given a deployment with sending off, when any tool call would lead to sending, then the server refuses it and Gmail receives no request to send.

#### The modules and what a caller may ask

- **The Gmail module.** `isSendingPath(path)` answers `true` exactly when the path, resolved against Gmail's base URL as `fetch` resolves it and with its escapes decoded, is `messages.send` or `drafts.send`. A path whose escapes do not decode answers `false`, and the function throws nothing.
- **The session agent, `GmailMCP`.** While sending is off, `api` refuses a sending request as its first act, with an error that names `ALLOW_SEND`, before the session owner check, the rate limiter, any token refresh and any fetch. A refused call records no request at the simulated Gmail or token endpoint.
- **The domain.** `CONTEXT.md`: sending is a request to Gmail that puts mail on the wire, a `POST` to `messages.send` or `drafts.send`. Use the words sending, sending off and sending tool in test names.

#### Facts and decisions

- FACT-016: dot segments resolve before a request leaves, percent escapes do not.
- FACT-018: the handler tests' harness, `makeAgent` and `boot`, calls handlers directly, so a handler error arrives as a rejected promise.
- FACT-022: how the harness makes the owner check or the rate limiter refuse. Set `owner` in the `storage` map that `makeAgent` returns to another account, and the owner check throws "different Google account". Put a `RATE_LIMITER` whose `limit` answers `{ success: false }` in the agent's `env`, and the rate limiter throws "rate limit reached". `bootThenTurnSendingOff` already replaces `env` by assignment, with no cast. Neither check fetches anything. Under bun, `decodeURIComponent` throws on the pathname of `/messages/%E0%A4%A`, and `/messages/sendfoo` resolves as written.
- DEC-001 Where the refusal of sending lives: in the Gmail request path, by the request, read at each use.
